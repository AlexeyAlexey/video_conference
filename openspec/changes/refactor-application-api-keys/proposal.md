# Proposal

## Why

Application API keys predate the stream server API keys change
(`2026-11-13-add-stream-server-api-keys`): they live in a generic
`api_keys` table, lack the `prefix` lookup column and `lock_version`
concurrency guard, and are managed through a grouped page with
route-driven forms and row deletion. Aligning them with the stream
server key model gives both scopes the same storage shape, secret
format, and management UX — and makes the prefix-based secret lookup
usable for application keys too.

## What Changes

- **BREAKING (internal)**: rename the `api_keys` table to
  `application_api_keys`; `Applications.ApiKey` maps to the new table.
- Add a unique, required `prefix` column holding the secret's
  `"aak_" <> prefix_id` lookup prefix (same role as the `"ssak_"`
  prefix on stream server keys); existing rows are backfilled with
  freshly generated prefixes.
- Add `lock_version` (default 1) with `optimistic_lock` per-field
  changesets — every update is guarded against stale writes.
- Drop API key name uniqueness: names are no longer unique within an
  application, matching stream server keys. Only the hashed secret
  stays unique per application.
- `Applications.create_api_key/1` stores `prefix` alongside the hash,
  generated by the shared `ApiKeySecret` module exactly like stream
  server keys (`"aak"` env prefix, independently generated `prefix_id`).
- Rework the `/stream-server-admin/api-keys` page to mirror the stream
  server API keys page: index-only LiveView with a required, searchable
  application filter (`?application_id=` URL param, prompt until one is
  picked), an event-driven add modal showing the application read-only,
  the one-time secret banner, an API KEY column showing `prefix` with a
  copy button, and per-field editing (rename modal, description modal,
  enabled checkbox). **BREAKING**: the `/new` and `/:id/edit` routes and
  the Remove action are removed — revocation is done by disabling.
- **BREAKING**: `Applications.update_api_key/2` and
  `Applications.delete_api_key/1` are removed in favor of per-field
  functions (`rename_api_key/2`, `edit_api_key_description/2`,
  `enable_/disable_api_key/1`).

## Capabilities

### New Capabilities

### Modified Capabilities

- `stream-server-applications`: the "API key records" requirement gains
  `prefix` and `lock_version` and drops name uniqueness; the
  "API key management grouped by application" requirement becomes a
  required-filter, per-field-edit page without deletion.

## Impact

- **Code**: `lib/video_conference/stream_server_admin_portal/`
  (`applications/api_key.ex`, `applications.ex`),
  `lib/video_conference_web/stream_server_admin_portal/`
  (`live/api_keys_live.ex`, `router.ex`)
- **Database**: new migration in `priv/stream_server_admin_portal_repo/migrations`
  (table rename, column adds, index changes, prefix backfill)
- **Behavior**: no API key deletion and no "all applications" key list
  remain; existing secrets keep working but pre-change secrets carry no
  recoverable embedded prefix — their stored `prefix` is a fresh
  generated value, since the hash cannot be reversed and no
  prefix-lookup consumer exists yet.
